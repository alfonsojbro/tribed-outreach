Run the Tribed daily outreach pipeline. Follow references/pipeline.md (Job C: SHIP → DRAFT → REPORT) exactly. This is an unattended run: every first-touch message is written to the review queue on the Tribed MCP (`accountId "digital_university"`) before anything sends, so the exact copy is always on the record. LinkedIn connection notes (`li_dm`) may then be approved by the run itself with `approve_outreach_draft` under Alfonso's direct-send authorization (2026-08-06) and shipped in the same run, up to the server-enforced daily cap. IG DMs and email still ship only after a human approves them in the dashboard (admin.tribed.io, Messaging > Review). LinkedIn sends through our self-hosted `linkedin` MCP; the tracker is the sequencer.

Preflight, LinkedIn: one `get_my_profile` call. On a session/login error, stop and tell the user to re-auth (`uvx mcp-server-linkedin@latest --import-from-browser`).

Preflight, Instagram (TWO steps, and step two is the one that gets skipped): `get_instagram_session_account_health({ accountId })` per account in `configuredAccounts`. A MISSING `queueingBlocked` or `actionControls` field is a stale MCP build, so it BLOCKS that account and gets reported by name, never read as healthy. `queueingBlocked: true` with `queueingBlockedReason: "action_controls_suppressed"` is not a stand-down on its own: call `verify_instagram_action_controls({ accountId })` first and honour the hold only if `after.suppressed` is still true. That check is read-only on Instagram, never clicks, and does NOT restart the block's window. If it errors or the build lacks it, the hold stands. Red for any other reason (dead session, engagement disabled) stands the account down without verifying. On 2026-08-17 an unverified 72h hold built from three profiles, two already recovered, idled four days of IG sending against a free budget and a 45-lead pool. An IG hold never blocks the LinkedIn or email legs. Full gate in references/pipeline.md.

1. SHIP (order matters — replies first):
   - Replies — three passes, because neither messaging tool paginates (`get_inbox` returns the ~10-20 newest and never clicks "Load more conversations"; `search_conversations` returns 10 rows whatever `limit` says). **A** `get_inbox({ limit: 50 })` for today's replies and anyone not on the tracker. **B (the real sweep)** every li lead at stage `replied` / `interested` / `demo_request`, plus any lead with a `data.demo_url` never sent: `get_conversation({ thread_id })` when `data.li_thread_id` is stored, else `search_conversations({ keywords: "<name>", limit: 2 })` → take the id off `references` (the `sections` text lies, it reads "No messages…yet!" on hits) → store it → read the thread. Cap 40/run, carry the rest on `reply_sweep_cursor`. **C** one rotated `search_conversations({ keywords: "demo" | "app" | "built" | "tribed", limit: 10 })` sampler. Then advance stage + store `data.li_thread_id`, draft Mode 2 replies for the user (never auto-send). Interested + no demo → build it (Job D, max 5/run). Demo built but never sent = a reply already missed; draft the delivery.
   - Acceptances: due leads awaiting acceptance → READ the connection degree (`get_person_profile`, or `search_people` with `network: ["F"]`). Only "· 1st" is an acceptance; a delivered message, a working or unavailable composer, and a reply prove nothing. If 1st: write `data.li_degree: "1st"` + `li_degree_checked_at` + `li_degree_source: "profile_top_card"` + `li_accepted_at` in one call, then `send_message` `data.li_followup_1` and schedule follow-up 2 (+3-4d). Reads 2nd or anything else: record that degree and clear any `li_accepted_at` in the same write, bump a day. Badge unreadable: stamp nothing, bump a day. 21+ days pending → lost.
   - Due follow-up 2: only for leads whose stored `data.li_degree` is `"1st"` — anything else gets its degree re-read instead of the closer. Then verify no reply via `get_conversation`, send `data.li_followup_2`, archive-if-quiet in 14d.
   - Approved drafts (`list_outreach_drafts({ status: "approved" })` + "error" retries): li_dm → `connect_with_person` with the note + upsert lead with follow-ups in `data`; ig_dm → upsert to the VA's list (owner from shipTarget); email → push to the Instantly campaign. `mark_outreach_draft_shipped` per draft. A draft that can never ship (pending invite already out, profile gone, replied elsewhere) → `reject_outreach_draft` with a concrete `reason`; never reject an `approved` draft.
   Caps: 15 connection requests, 25 messages, 25 IG handoffs, 50 emails per run — but the worker's warmup ramp at `https://li-worker.tribed.io/health` is the real budget when it is lower, and its counters are UTC-day keyed (an early-morning local run lands in the previous UTC day, so a second run the same local day can double the ramp; one run per UTC day). A `connect_unavailable` on a creator profile almost never means closed to requests — it means Follow is the primary button and Connect sits under the More menu; read the payload's `observed_state` / `connect_route` before treating the lead as uninvitable, and never reject a draft on `connect_unavailable` alone. A sent message can take ~20 minutes to appear in the thread — "not in thread" minutes after `sent: true` is NOT a phantom send; never resend on a fresh thread read, recheck next run. STOP the LinkedIn leg on any checkpoint/captcha/verification error and report it.

2. DRAFT — IG-first cross-channel discovery plus rotated `search_people` sourcing (rotation via `get_outreach_state("query_rotation")`). Skip-check each candidate (`list_outreach_leads({ search })`), ICP-gate (2,000+ followers OR creator/influencer flag; Apify `harvestapi/linkedin-profile-scraper` for bulk), personalize survivors in the Tribed voice (rule zero: one real anchor; connection note + case-study follow-up + video follow-up), and queue with `queue_outreach_drafts` (kinds li_dm / ig_dm / email). Anchor-less prospects queue with anchor omitted (held) — never write generic.

   Then ship the day's LinkedIn first touches, within whatever invite budget phase 1 left: `approve_outreach_draft({ draftIds: [<the li_dm drafts just queued>], accountId: "digital_university" })`, read `remainingToday` from the result as the real budget, then ship each approved one exactly as in phase 1's li_dm step. Anything refused comes back with its reason — act on it, never route around it. `ig_dm` and `email` drafts are NOT approved here; they stay pending for the dashboard.

3. REPORT — `set_outreach_state({ key: "daily_run", ... })` with per-channel counts (note: `get_outreach_state` returns `value` as a JSON STRING — parse it, and trust `updatedAt` for when it was written), snapshot the funnel with `get_outreach_lead_counts` → `upsert_outreach_metrics` (never tally `list_outreach_leads` pages — that reports a floor as a total), and `send_admin_report`: replies (split by pass), the acceptance line with its denominator (checked / accepted / unreadable / still unswept — never a bare "zero acceptances"), sends, invites, drafts queued/held (nudge to the Review tab), drafts rejected with reasons, demos built, stale invites, errors. Then `close_session` — the LinkedIn browser session is never left alive after the run.

Never infer a LinkedIn acceptance from messaging success. Only a read connection degree of "· 1st" counts, and the proof (`li_degree`, `li_degree_checked_at`, `li_degree_source`) goes on the lead beside every `li_accepted_at` — and it is on YOU to write it: the MCP accepts an acceptance stamp with no proof attached and no complaint, so nothing but this discipline stops a false stamp. Do not work out-of-ICP prospects. The run may approve its own `li_dm` drafts and nothing else — `approve_outreach_draft` refuses every other kind, and it can never un-approve, rewrite, or resurrect a draft a human decided on.
